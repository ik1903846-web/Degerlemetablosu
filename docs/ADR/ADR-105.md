# ADR-105: Build Environment İzolasyonu — `cross-env` ile NODE_ENV Sabitleme

**Durum:** Kabul edildi
**Tarih:** 25 Nisan 2026
**Faz:** 1.1 (Monorepo iskelet)
**İlgili ADR:** ADR-022 (Stack), ADR-023 (CI/CD)

## Bağlam

Faz 1.1 boş Next.js 15.5.15 scaffold'unda `pnpm --filter web build` 5 ardışık deneme boyunca hata verdi:

```
Error: <Html> should not be imported outside of pages/_document.
Error occurred prerendering page "/404".
```

Şüpheliler ardışık olarak elendi:

| Şüpheli | Eleme yöntemi |
|---|---|
| Turbopack build | `--webpack` ile build dene → aynı hata |
| React 19 | `react@18 react-dom@18` downgrade → aynı hata |
| Özel kod | `apps/web/` taraması → tamamen vanilla scaffold |
| Pages Router kontaminasyonu | `pages/`, `_document`, `_error`, `_app` yok |
| `next.config.ts` özelleştirmesi | Boş, default |

Asıl bulgu **build çıktısının ilk satırında** — 5 build boyunca görmezden gelinen uyarı:

```
⚠ You are using a non-standard "NODE_ENV" value in your environment.
```

`/proc/$$/environ` ile bash subshell env dump'ında:

```
NODE_ENV=development
CLAUDE_CODE_EXECPATH=...claude.exe
```

Karşılaştırmalı tarama:

| Konum | NODE_ENV |
|---|---|
| Windows User-level env var | _(boş)_ |
| Windows Machine-level env var | _(boş)_ |
| `~/.bashrc / .profile / etc.` | _(yok)_ |
| `/etc/environment, /etc/profile` | _(yok)_ |
| Native PowerShell session | _(boş)_ |
| **Claude Code Bash tool subshell** | `development` |

Sonuç: Kullanıcının makinesi tertemiz. `NODE_ENV=development` Claude Code Node süreci tarafından spawn edilen Bash subshell'lere sızıyor (PowerShell tool'una sızmıyor — sadece Bash). Next.js'in `next build` sırasında otomatik `NODE_ENV=production` ataması bu inherited değer tarafından override ediliyor; build "App Router + dev mode" garip karışımına düşüyor ve Pages Router'ın `<Html>` component'ini arıyor.

## Karar

`apps/web/package.json` build script'i `cross-env NODE_ENV=production` wrapper'ı ile sarmalanır:

```json
"build": "cross-env NODE_ENV=production next build"
```

`cross-env` paketi `devDependencies`'e eklenir.

## Sonuçlar

### Olumlu

- **Defensive:** Hangi ortamdan çalıştırılırsa çalıştırılsın (Claude Code Bash, normal PowerShell, CI runner, Docker container) build deterministik şekilde `NODE_ENV=production` görür.
- **CI/CD uyumu:** GitHub Actions, Vercel, Railway zaten production set eder; cross-env zarar vermez.
- **Faz 1.4 validation testleri (Heineken/ABN Amro/Tube Industries) Claude Code üzerinden koşacak** — her seferinde elle prefix yazma yükü kalkar.
- **Hata kaynağını dokümante eder:** Gelecek geliştirici aynı tuzağa düşmez.

### Olumsuz

- 5KB ek dependency.
- Build script'i tek satır daha uzun.
- Asıl problem (Claude Code env sızıntısı) bu projede çözülmüyor; sadece yan-etkisi maskeleniyor. Anthropic'e bug raporu yapılabilir (out of scope).

### Notlar

- Bu sızıntı sadece **build** komutunu etkiler. `dev` script'i `NODE_ENV=development` zaten istediği için sorun yok.
- `start` script'i prod runtime — CI/prod ortamında zaten `NODE_ENV=production` olur.
- Test ve diğer komutlar eklendiğinde benzer guard gerekirse pattern aynı: `cross-env NODE_ENV=test ...`.

## Alternatifler (Reddedildi)

1. **Hiçbir şey yapma, her seferinde elle `NODE_ENV=production pnpm build`:** Hata kaynağı, otomatize edilemez.
2. **Sistem env'inden `NODE_ENV` kaldır:** Kullanıcının sisteminde zaten yok. Sızıntı Claude Code süreçten geliyor — biz çözemeyiz.
3. **Bash wrapper script:** Karmaşık, cross-platform değil.
4. **`.env.production` dosyasında `NODE_ENV=production`:** Next.js docs açıkça yasaklıyor (NODE_ENV `.env`'lerden okunmaz).
